# Compatibility and intentional limits

## Sublime Text

Requires Sublime Text 4 and is tested with build 4215. Sublime Text 3 is not
supported. `.python-version` contains `3.8`, which selects the Python 3.8 plugin
host on older builds and Python 3.14 on build 4213 and newer.

The package only uses platform-neutral Sublime APIs and standard-library
Python. CI tests it in Sublime Text on Linux; Windows and macOS were tested
separately, not on every change.

## Markdown profiles

**CommonMark**: headings, emphasis, links/images, code spans/fences,
blockquotes, ordinary lists, thematic breaks, and raw HTML comments/insertions.
No tables, strikethrough, task syntax or footnotes are generated by built-ins.

**GitHub Flavored Markdown (default)**: the common core plus tables,
strikethrough and task lists. GitHub's website has additional extensions beyond
the published GFM specification. In particular, this package reserves its
footnote generator for the MultiMarkdown profile rather than labeling it GFM.

**MultiMarkdown**: the common core plus tables and footnotes. The menu avoids
claiming GFM-only task syntax as standard MultiMarkdown.

**CriticMarkup** is a separate annotation syntax, enabled by default and
independently disabled with `enable_critic_markup: false`:
`{++addition++}`, `{--deletion--}`, `{~~old~>new~~}`, `{==highlight==}`,
`{>>comment<<}`. Plain GitHub Markdown does not render these as review markup.

“Additions” also has a broadly usable **Insertion** action using raw HTML
`<ins>…</ins>`. Rendering and HTML sanitization ultimately depend on your
viewer; comments may be hidden, raw HTML disabled, or styling overridden.

Profiles filter available insertions. They do not parse an entire document,
validate conformance or convert existing Markdown between dialects.

## Editing boundaries

This is a focused markup editor, not a replacement for a Markdown parser.
Select the text/lines to change. Simple marker toggles are conservative;
complex nested constructs, existing tables, nested mixed lists and renderer-
specific extensions may require manual adjustment. Inspect source after edits;
Undo always remains available.

Native menu entries cannot be individually colored or assigned fonts through
the documented API. The **Styled Picker** instead shows example-only rows,
highlighted by the active Markdown syntax and Sublime color scheme, with live
appearance refresh. Manual picker style overrides are no longer used.
Native grouping is fixed; picker ordering, hidden actions and labels are
settings-driven. Custom formats are in a chooser rather than generated native
menu files. This avoids stale generated packages after uninstall.

### Empty submenu headings on Windows

Sublime's Windows menu renderer honors command visibility for individual
actions, but not for submenu containers. Consequently, disabling CriticMarkup
hides its actions but can leave an empty **Review** heading. With
`markdown_only: true`, non-Markdown files can retain empty **Headings**,
**Lists**, **Insert**, and **Review** headings alongside **Settings…**.
Linux hides them as expected; macOS draws submenu headings like Windows. With `show_in_context_menu: false`, every action,
picker, repeat and profile entry is hidden on all platforms (they carry a
menu-only `"context": true` argument), so Windows and macOS keep only the
**Markdown Formatting** heading with **Settings…** and possibly empty group
headings.

The package deliberately preserves hover-to-open native submenus rather than
replacing them with click-to-open choosers or writing generated menu files.
This is an upstream limitation, tracked in
[submenu visibility](https://github.com/sublimehq/sublime_text/issues/1859)
and [empty submenu containers](https://github.com/sublimehq/sublime_text/issues/1095).

No render preview, autosave reformatting, external formatter, server, network
request, telemetry or default shortcut is installed.
